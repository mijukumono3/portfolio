# LoL Coach 実装計画

設計書: `docs/superpowers/specs/2026-11-19-lol-coach-design.md`

各タスクは「失敗するテストを書く → 実行して失敗を確認 → 最小実装 → 通過確認 → コミット」の順で進める（UI タスクはビルドと画面確認で検証）。

## Task 1: 雛形

- `lol-coach/` に package.json、tsconfig、vite.config.ts、vitest 設定、`.gitignore`（node_modules, dist, release）
- 依存: react, react-dom / dev: electron, electron-builder, vite, @vitejs/plugin-react, typescript, vitest, @types/react, @types/react-dom
- 検証: `npm test`（空でも通過）、`npm run build`

## Task 2: 3 戦セット判定 `src/core/session.ts`

テストケース:
- [] → continue
- [L] → continue / [L,L] → stop（2 連敗）
- [W,L,L] → stop / [L,W,L] → stop（3 戦 1 勝）
- [W,W] → continue / [W,L,W] → continue（2 勝 1 敗）/ [W,W,W] → continue
- [W,L,W,W] → continue / [W,L,W,L] → stop（続行中に敗北）

## Task 3: マッチアップ判定 `src/core/matchup.ts`

テストケース（教科書のルール）:
- トップ: tank vs tank → X、tank vs bruiser → X、tank/bruiser vs ranged: Lv6 前 X / 後 O、bruiser vs bruiser → O、味方 ranged → O（初手ターンはトップ）
- ミッド: 味方ロームT1 → O（Lv 不問）、T2 → Lv6 以降 O、T3 → 状況、遠距離ファーム → X（視界確保）、レーン戦強い → O、近接 vs 近接 → 最重要
- ボット: サポート 70% / ADC 30% の重み。CC サポ 1, ソフト CC 0.5〜1, ユーティリティ 0, 牽制 1, ローム 1 / ADC レーン強 1, 五分 0, CC 0.5〜1
- 全レーン同値なら ボット > ミッド > トップ

## Task 4: 科目スコア `src/core/scores.ts` と復習キュー `src/core/review.ts`

- 回答履歴から科目別正答率（未回答科目は null）、最低科目の推奨
- 誤答 ID を先頭に、正解したら除外

## Task 5: 教科書データ化 `scripts/build-textbook.mjs` と `src/core/search.ts`

- 入力テキスト → 章配列 `{id, title, level, body}` / ワークブック設問配列
- search: 大文字小文字無視、章ごとのヒット件数と抜粋

## Task 6: クイズデータ `src/content/quiz.ts`

- 7 科目それぞれに選択式問題、解説と参照章 ID。データ整合性テスト（正解インデックスが範囲内、参照章が存在、科目が有効）

## Task 7: 永続化と Electron

- `electron/main.cjs`, `electron/preload.cjs`: `store:load` / `store:save` IPC で userData/lol-coach.json
- `src/store.ts`: window.lolStore があれば IPC、なければ localStorage

## Task 8: 画面

- App シェル（サイドナビ）＋ Home / Reader / Drill / Workbook / Matchup / Session

## Task 9: 検証とパッケージ

- `npm test`、`npm run build`、Playwright でレンダラーのスクリーンショット確認
- `npm run dist:win` で Windows zip を生成
- コミット・push
